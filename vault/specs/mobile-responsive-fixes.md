# Spec: Mobile-адаптив — устранение горизонтального переполнения

## Description

На телефоне (это installable PWA, целевая ширина ≈ **360–414px**) «много где элементы
вылезают за границы экрана» — появляется горизонтальный скролл, контент упирается в края.
Цель: пройтись по всем экранам и убрать переполнение по ширине, не меняя десктоп-вид.

Это **frontend-only** правка стилей (Tailwind-классы + пара строк в `globals.css`). Схему БД и
API не трогаем. Подход: **mobile-first** (базовый класс = телефон, `sm:`/`md:` = крупнее).

> **Метод аудита (честно):** браузерный инструмент не смог сжать окно до мобильной ширины
> (`resize_window` игнорируется, `innerWidth` застрял на 1577px), поэтому находки ниже — из
> **анализа кода** (точные file:line). Финальная проверка — на реальном телефоне через LAN
> (`http://192.168.0.166:3000`) и в Chrome DevTools device mode (см. Verification). Список —
> приоритизированные кандидаты; на устройстве может всплыть ещё.

## User Stories

- Как пользователь с телефона, я хочу, чтобы **ни одна страница не скроллилась вбок**, чтобы читать и нажимать было удобно одной рукой.
- Как пользователь, изучающий немецкий, я хочу, чтобы **длинные немецкие слова** (составные существительные вроде «Geschwindigkeitsbegrenzung») переносились, а не уезжали за край.
- Как пользователь на узком экране, я хочу, чтобы **ряды кнопок/бейджей, формы, диалоги и меню** помещались по ширине и переносились, а не обрезались.
- Как админ с телефона, я хочу, чтобы **таблицы** скроллились внутри своей карточки, а не ломали всю страницу.

## Data Model

**Нет.** Чисто визуальная правка — таблиц/колонок не добавляем и не меняем.

## Business Logic (правила, которые принимаем как конвенцию)

- **Mobile-first**: базовый класс описывает телефон; увеличения — через `sm:`/`md:`. Никаких немодифицированных «широких» гридов (`grid-cols-3/4` без `grid-cols-1/2` базы).
- **Фиксированные px-ширины запрещены на потенциально-широких рядах**: вместо `w-44/w-56/w-64` — `w-full sm:w-…` или `w-[min(…,Nvw)]`.
- **Ряды из нескольких детей** (кнопки/бейджи/инпуты) — всегда `flex-wrap`.
- **Длинный контент** (немецкий, email, код) — переносится (`overflow-wrap`), не `whitespace-nowrap`.
- **`truncate` требует `min-w-0`** по цепочке flex-родителей.
- **Таблицы** — только внутри `overflow-x-auto`.
- Закрепляем в `vault/atlas/conventions.md` → Frontend patterns после внедрения.

## Edge Cases

- **Очень узкие (≤320px, iPhone SE)**: 2×2-гриды и `w-full` инпуты должны держаться; проверить отдельно.
- **Немецкие составные слова** длиной 25+ символов в заголовке/бейдже — перенос обязателен (блок A + E).
- **Динамические счётчики** («135», «133 слов · 2 грамм.» на дашборде) — не должны распирать карточку: `min-w-0` + перенос.
- **Диалог с длинным контентом** (ошибки, длинные русские подсказки) — вертикальный скролл, не горизонтальный; высота капится (`max-h-[85vh] overflow-y-auto` при необходимости).
- **Клавиатура на мобильном** + dock-композер (`fixed bottom-0`): не перекрывать поле; визуально проверить.
- **Landscape** телефона — sidebar всё ещё скрыт (`md:` = 768px), мобильная навигация остаётся.

## Verification

1. **Реальное устройство (главное):** открыть на телефоне `http://192.168.0.166:3000` (PWA в одной сети) и пройтись по всем экранам — нет горизонтального скролла, ничего не обрезано.
2. **Chrome DevTools device mode** (iPhone SE 375px, Pixel 7 412px) — десктоп-агенту недоступен напрямую, но человеку — быстрый способ.
3. **JS-детектор переполнения** (запускать в консоли на каждой странице):
   ```js
   const vw=innerWidth,off=[];document.querySelectorAll('body *').forEach(e=>{const r=e.getBoundingClientRect();if(r.width&&(r.right>vw+1||r.left<-1))off.push([e.tagName,Math.round(r.right),String(e.className).slice(0,50)])});console.log(document.documentElement.scrollWidth>vw+1?'OVERFLOW':'ok',off.slice(0,15))
   ```
   Цель: `ok` и пустой список на каждом экране при 360–414px.
4. `npx tsc --noEmit` · `npm run build` — классы валидны, ничего не сломалось на десктопе.
5. Светлая и тёмная темы.
