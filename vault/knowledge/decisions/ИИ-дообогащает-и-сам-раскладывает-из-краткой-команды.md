# ИИ дообогащает и сам раскладывает из краткой команды

<!-- Updated: 2026-06-27 | список слов в одном сообщении → N proposals в одном турне (раньше модель добавляла только первое и ждала) -->


**Решение.** Ассистент агентный: из короткой реплики пользователя («добавь слово aufstehen», «запиши это правило», «разбери мою домашку») он делает ВСЮ работу сам — **думает** (reasoning ON, не minimal), дозаполняет все нужные поля и сам кладёт результат куда нужно. Пользователь не должен указывать детали, которые модель может вывести.

**Почему.** Прямая просьба владельца: «иишка с таким подходом должна думать… я могу написать просто "добавить слово", оно должно добавить по нему всё что нужно и куда нужно, и так в целом должна работа быть в системе». Это и есть ценность инструмента — снять рутину, а не плодить формы.

**Как применяем.**
- **Auto-enrich.** Для слова модель сама выводит: часть речи; для существительных — Artikel (der/die/das), Plural, Genitiv; для глаголов — отделяемость+приставка, вспомогательный (haben/sein, рассуждая Bewegungs-/Zustandsverb), Partizip II, Präteritum, неправильный презенс, рефлексивность, управление падежом; перевод на русский; CEFR-уровень; теги; 1–2 примера с переводом. Аналогично для грамматики/упражнений.
- **Auto-route.** Модель сама выбирает `target_type` и привязку (текущий `Unit`, нужный `GrammarTopic`); Apply-диспетчер по умолчанию кладёт в текущий юнит. Может предложить второй `propose` — `SRS_CARD` для повторения.
- **Auto-group.** <!-- Updated: 2026-06-14 | vocab-grouping --> Для слова модель кладёт его в широкую группу + узкую подгруппу (`Еда→Овощи`), **переиспользуя** существующую таксономию из envelope-блока «Vocabulary groups» (`{g:id}`-токены в слое 02), а не плодя близкие дубли; Apply делает create-or-reuse и проставляет `VocabEntry.groupId` в той же транзакции. Реализация: [[vocab-grouping]].
- **Decompose.** Большая просьба → несколько proposals (по ошибке на исправление + карточки слов/грамматики). **Список — это много изменений:** когда пользователь перечисляет несколько слов в одном сообщении («angeln, fressen, die Wolle, Feder, …»), модель эмитит ОТДЕЛЬНЫЙ `propose(VOCAB_ENTRY)` на КАЖДОЕ слово **в том же турне** (одна дообогащённая карточка на слово), а не «начнём со слова X» и пауза. Пайплайн это уже поддерживал — роут `app/api/ai/chat` собирает ВСЕ `toolCalls` стрима и шлёт `proposal`-event на каждый, провайдер (`gemini.ts`) йелдит по `functionCall`-парту, док рендерит массив карточек. Правка чисто в персоне (раздел «WRITES ARE PROPOSALS ONLY» + «Decompose» в `layers.ts`) + усилена в описании tool (`propose/tool.ts`: «multiple `propose` calls in the same response — one per item»). Проверено headless: `npm run ai -- propose "…9 слов…"` → 9 карточек в одном ответе (с нормализацией `die Beine→das Bein`, `beissen→beißen`). UI: в доке кнопка «Применить все · N» (`assistant.applyAll`) над пачкой из ≥2 предложений — опциональный `applySignal`-проп на `ProposalCard`.
- **Think first.** `reasoningEffort` для chat/vocab/homework/grammar = `low` (не `minimal`), чтобы морфология/падежи были верны. Баланс со стоимостью free-tier — настраивается в `lib/ai/features/templates.ts`.
- Уточняющий вопрос — только при настоящей неоднозначности; иначе действовать.

Реализация: правило зашито в `SYSTEM_PERSONA` (раздел «BE PROACTIVE: AUTO-ENRICH & ROUTE») в `lib/ai/envelope/layers.ts`.
