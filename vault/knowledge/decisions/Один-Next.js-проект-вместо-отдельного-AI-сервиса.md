# Один Next.js-проект вместо отдельного AI-сервиса

**Решение.** Весь продукт — один Next.js (App Router, TS): фронт + бек (Route Handlers) + AI-библиотека (`lib/ai`). НЕ повторяем разделение ToonyGamy (.NET бек + отдельный Python `toonygamy-ai`).

**Почему.** В ToonyGamy отдельный Python-сервис оправдан тяжёлыми image/ML-моделями и общим беком для web+mobile. У нас на старте только текст на Gemini — отдельный сервис добавил бы деплой/латентность/сложность без выгоды. TS-порт context engine живёт как обычная библиотека и импортируется роут-хендлерами. `lib/ai` остаётся framework-agnostic (зависит только от `lib/db` и `fetch`/`crypto`), так что при необходимости его можно вынести в отдельный сервис позже без переписывания.

**Владелец явно просил:** «бек на next.js и фронт react».
