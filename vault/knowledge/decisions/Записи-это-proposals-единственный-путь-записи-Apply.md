# Записи — это proposals, единственный путь записи Apply

**Решение.** У модели НЕТ инструмента записи в БД. Единственный способ что-то сохранить (слово, грамматику, исправление ДЗ, упражнение) — вызвать инструмент `propose`, который создаёт карточку `Proposal` (status PENDING). Пользователь нажимает **Apply** → диспетчер Apply (единственный writer, проверяет ownership, идемпотентный) распиливает payload в типизированные строки. Refine = supersede+перегенерация, Discard = отмена. Ни Refine, ни Discard не пишут в цель.

**Почему.**
- Безопасность: даже скомпрометированный prompt-template не может ничего записать — нет инструмента записи; писать может только Apply-диспетчер.
- Контроль пользователя: ничего не меняется без явного клика; виден аудит-трейл.
- «DB is the memory»: только applied-поля попадают в следующие envelope-слои 02/03 — замыкается петля обучения.

**Следствие.** Изменение формы payload требует синхронной правки: zod-схема (`propose/persist`) + applier (`propose/dispatch`) + prompt-template + UI карточки. См. [[dependency-graph]].
