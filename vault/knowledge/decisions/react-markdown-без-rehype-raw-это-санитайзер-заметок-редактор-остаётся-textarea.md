# react-markdown без rehype-raw — это санитайзер Заметок; редактор остаётся textarea

**Контекст.** Вкладка «Заметки» из read-only превратилась в **markdown-блокнот**: страница
`app/(app)/notes/[id]/page.tsx` получила тогл read/edit.
- **read** — рендер markdown через новый `components/writing/markdown-view.tsx` (`MarkdownView`);
- **edit** — тот же `Composer`, что и на создании, привязанный к `PATCH /api/notes/[id]`.

## Решение 1 — рендер через `react-markdown` + `remark-gfm`, БЕЗ `rehype-raw`

`MarkdownView` рендерит **доверенный markdown (GFM)**, но **сознательно НЕ подключает
`rehype-raw`**. Это и есть стратегия санитайзинга: без `rehype-raw` сырой HTML в тексте
заметки **никогда не превращается в DOM** — вставленный `<script>` / `<img onerror=…>`
остаётся инертным текстом и не исполняется. Это прямое продолжение core-принципа №3 проекта
(«весь авторский текст пользователя — инертные данные»): тот же инвариант держится не
`sanitize()`+`<data>`-обёрткой (та — для *ввода в конверт*), а **выбором пайплайна рендера**.
Обе библиотеки (`react-markdown`, `remark-gfm`) уже были в проекте — новых зависимостей не
добавляли.

Дополнительная защита от разъезда вёрстки (mobile-first, [[conventions]]):
- таблицы обёрнуты в свой `overflow-x-auto` → широкая таблица скроллится **в себе**, не
  панорамируя всю заметку;
- `img` кэпится `max-w-full` → картинка не распирает контент.

## Решение 2 — редактор остаётся `<textarea>` (`Composer`), не WYSIWYG

Правка markdown идёт в том же plain-text `Composer` (`german` включён на детали заметки),
а НЕ в rich-редакторе. Почему: markdown — это **простой текст**, поэтому панель немецких
спецсимволов (`GermanCharBar`, вставка `ä ö ü ß` в курсор) продолжает работать без изменений
— она умеет вставлять в `<textarea>`, а не в contenteditable. WYSIWYG сломал бы этот UX и
всё семейство «удобного письма» ([[автогрост-textarea-и-вставка-умлаутов-в-курсор]]).
`Composer` ради этого получил опциональный проп `hint` (мелкая подсказка про markdown под
счётчиком слов).

## Решение 3 — Заметки = блокнот, Домашка = вариант задачи; переход через КОПИЮ

Кнопка «Отправить в домашку» (`sendToHomework`) **копирует** содержимое заметки в новую
`Homework` со `status: SUBMITTED` (`POST /api/homework`, тело `title`/`rawInput`/`entryDate`),
**не перемещая** заметку — она остаётся в блокноте. ИИ-проверку домашки пользователь потом
запускает сам (вручную). Так закрепилось разделение ролей:
- **Заметки** — свободный блокнот: папки/группы (домен `NOTE`), markdown, опциональный
  ИИ-разбор («Разобрать» → structured `newVocab`/`grammarPoints`/`todos`);
- **Домашка** — вариант «задачи»: статус-lifecycle (`SUBMITTED`→…) + пайплайн коррекции.

Копия, а не перенос, — потому что у заметки и домашки разные жизненные циклы; исходный
конспект нужен и после того, как из него сделали задание. Обратной связи `Homework → note`
пока нет — отложено в [[post-mvp-backlog]].
