# Rolling summary треда написан, но никем не вызывается → старые треды молча теряют контекст

## Факт
Архитектура обещает «rolling summary past a watermark» ([[architecture]]), и эндпоинт `POST /api/threads/[id]/summarize` реализован (фоновая, небиллируемая модель, порог 20 сообщений, оставляет 4 verbatim). Но его **никто не вызывает** — ни крон, ни клиент, ни роут чата. Единственный вызов — dev-CLI `scripts/ai-cli.ts summarize` (работает по Phase-1 JSON-сиду, не по живым тредам).

## Следствие
- `ChatThread.threadSummary` всегда `null`, `ChatMessage.isSummarized` всегда `false`.
- Модель видит только последние `THREAD_TAIL=12` реплик (`lib/ai/envelope/caps.ts`). Когда тред перерастает 12 реплик, ранний контекст **молча выпадает** — ни в резюме, ни в хвосте. UI при этом показывает 24 (`/api/threads/resolve`).
- Это **не** причина бага с «ответил на старое» (тот — про висящий user-турн, см. [[оборванный-ответ-оставляет-висящий-user-турн-модель-отвечает-на-старое]]), а отдельный латентный гэп.

## РЕШЕНО 2026-06-17 — суммаризация активирована (rolling)
Вынес логику в `lib/ai/thread/summarize.ts` → `summarizeThreadIfNeeded(threadId, userId)`:
- **Автозапуск** из роута чата **после закрытия SSE-стрима**, только при успехе — фоном, не блокирует ответ, `isBackground`+`skipRateLimit` (не биллится). Self-healing: пропущенный прогон доберётся на следующем турне.
- **Rolling**: при `live-турнов ≥ SUMMARIZE_AT (24)` сворачивает все, кроме последних `KEEP_VERBATIM (= THREAD_TAIL = 12)`, **вместе с предыдущей сводкой** (предыдущая `threadSummary` подаётся в инпут → консолидация, а не перезапись). Итог кап `CAPS.THREAD_SUMMARY (4000)`.
- Эндпоинт `POST /api/threads/[id]/summarize` теперь тонкая обёртка над сервисом (ручной/крон-триггер). Промпт фичи `thread_summarize` усилен под слияние сводок.

Теперь модель видит `summary + последние 12 вербатим` — контекст за пределами окна больше не пропадает.

## Также (2026-06-17)
Кнопка «Новый чат» (`POST /api/threads/[id]/clear`) — мягкий сброс треда: прячет старые турны из окна и UI (без удаления из БД), чтобы длинный замусоренный тред можно было начать заново.
