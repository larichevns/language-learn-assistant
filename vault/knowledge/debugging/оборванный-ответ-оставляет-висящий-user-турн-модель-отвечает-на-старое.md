# Оборванный ответ оставляет висящий user-турн → модель отвечает на старое сообщение

## Симптом
Пользователь не заходил 2 дня, открыл существующий тред, отправил **новый** запрос - модель сначала ответила на **прошлое** (давнее) сообщение, и только потом на новое.

## Корень
Цепочка из четырёх звеньев:
1. Роут чата грузит историю **до** записи нового сообщения и пишет ассистентский турн **только** после успешного стрима (`app/api/ai/chat/route.ts`).
2. Если прошлый ответ не записался - стрим оборвался (закрыл вкладку, таймаут `maxDuration=60`, rate-limit, обрыв сети) **или** записался пустым (модель вернула только proposal без текста, билдер выкидывал пустой турн) - тред заканчивается **висящей USER-репликой без ответа**.
3. На следующий запрос `loadHistory` подтягивает её в хвост, а билдер дописывает новое сообщение сразу после → **два user-турна подряд** (`lib/ai/envelope/builder.ts`).
4. Gemini-провайдер **склеивает подряд идущие однородные турны в один** (`toContents`, `lib/ai/providers/gemini.ts`). Модель видит одну реплику с двумя вопросами и отвечает на первый (старый).

## Фикс (defense in depth)
- **Билдер** (`buildEnvelope`): фильтрует пустые турны и **срезает хвостовые user-турны** - история перед живым сообщением всегда заканчивается на model-турне. Универсально для всех фич, кэш-префикс (block0/block1) не трогается. Покрыто `builder.test.ts`.
- **Роут чата**: ассистентский турн пишется только при непустом тексте, **включая частичный ответ при Stop/обрыве**; пустые турны больше не создаются. Abort (`req.signal.aborted`) трактуется как штатная остановка, без `error`-события.
